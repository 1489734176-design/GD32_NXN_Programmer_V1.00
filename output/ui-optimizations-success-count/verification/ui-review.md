## 核对结果

- 仅手动主界面固件行的中键进入列表；列表左/右短按、长按、连发只移动候选，长右不会切换模式。中键确认；长中取消，包括 USB 忙时取消。既有扫描层左右 500ms 长按、100ms 连发保持。
- 六行名称缓存为静态数组，页内/跨页/首尾回绕、当前固件定位、最后不足六行、空目录和目录读取/关闭失败均有明确边界。最多 31 字节 ASCII 名称在 224×36 字段内按 28+3 字符换成两行，目录/OPT/过长及非 ASCII 名称被过滤。
- 浏览只枚举目录，不读正文、不更新有效选择或校验值。确认候选时完整读取 SUM32，再检查配套 OPT；全部成功后才一起写 app_data、checksum、OPT 标记及 dirty。主文件/OPT 错误留在列表，旧有效选择及保护标记保持；随后可继续移动或取消。
- 确认返回后由既有主任务 `save_program_selection()` 持久化，dirty/保存失败仍阻止烧录。USB 文件服务与列表访问均在主任务串行进行；文件变更使列表缓存失效，prepare 完成会退出列表并使主界面缓存失效。
- `show_top()` 在充电/充满均画电池左侧 8×16 闪电，拔出清黑对应矩形。温度区结束于 x=140，闪电占 x=140..147，电池从 x=152 开始，无覆盖；换页强制重绘 top，后续相同状态无像素写入。
- 已查看 `task/ui/chooser-preview.png`：充电、充满、拔出、两页列表、长名称换行与底部中文提示可见且没有越界/残影。

## 4KB 栈边界

真实链接器 `offline.htm`：mode3 自身栈帧 88B，最大调用深度 740B；加上 run_task 自身 80B，列表路径静态最大约 820B。scan_firmware_page 自身 32B，select_firmware 自身 128B。新增六名称缓存 192B 位于静态区，没有放入任务栈，也没有递归或按文件数分配的栈数组。

全程序静态最大仍为原 mode4 路径的 1956B，未因列表形成新峰值；run_task 配置仍为 1024 个 32 位栈字（4096B）。链接器提示仍含 cycles / untraceable function pointers 的未计量部分，因此这些是静态调用图证据，不等同于实板高水位测量；本轮未发现新增栈风险。
