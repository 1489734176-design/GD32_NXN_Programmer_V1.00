## 初审实质发现（历史）

### [P1，已关闭] OPT 文件异常被静默保存成“不编程 OPT”

- 位置：`GD32-HID/GD32-HID/USER/APP/run.c:441-444`。
- 新轮选逻辑预置 `app_data.opt_enable = 0`，仅在 OPT 能成功打开且大小非零时置 1；任意打开错误、零字节文件、关闭错误都会保留/恢复为 0，随后正常保存选择并显示待操作。
- 触发：目录内有正常 `A.bin` 和应当配套的 `A_opt.bin`，轮选时让 OPT 打开返回 `FR_DISK_ERR`，或保留一个零字节 OPT 文件。主固件的 checksum 可正常通过；已选用扩展算法时，后续 `mode4()` 在第 1038 行直接跳过 OPT，且第 1222-1223 行可以置成功，第 1235 行可提交成功计数，最后显示绿色成功。原选择逻辑将 `opt_enable` 置 1，缺失/坏 OPT 会进入失败路径；新增探测把这种错误降格为非加密烧录。对产品的读保护功能，这会产生未保护却按成功交付的芯片。
- 修复方向：仅把确定的“不存在”视为可选 OPT 缺省；存在但为空、I/O 或关闭错误应保留明确失败并阻止保存为可烧录的无 OPT 选择。若实际策略要求某固件必带 OPT，继续保留该要求。
- 可验证：向轮选的 OPT `f_open` 注入 `FR_DISK_ERR`，以及提供 0 字节 OPT；均应看到明确失败，不能把 `opt_enable=0` 的选择持久化后得到绿色成功。

### [P2，已关闭] 一个坏文件会阻止轮选到它后面的正常文件

- 位置：`GD32-HID/GD32-HID/USER/APP/run.c:445-447`，关联第 406-422 行。
- 轮选仅用当前 `app_data.bin_name` 作为迭代位置，文件读取失败后却清空该名字。下次按中键便从目录首项开始，无法越过失败项。
- 触发：目录枚举顺序为 `A.bin`（有效）、`B.bin`（0 字节或持续读取失败）、`C.bin`（有效）。从 A 轮选 B 后进入 `invalid_file` 并清空名字；下一次回到 A，再下一次又失败于 B，C 永远不可选。若首项就是坏文件，所有后续正常固件都不可选。单页已移除独立选择列表，因此设备按键没有绕过路径。
- 修复方向：为浏览保留独立的候选位置，或在有界的一轮目录遍历内跳过不可烧录项；可烧录选择仍应安全失效。仅保留旧有效选择不能解决被坏文件卡住的问题。
- 可验证：用上述三个文件连续触发中键，确认最终能到达 C，且坏文件不会被用于烧录或保留旧 checksum。
