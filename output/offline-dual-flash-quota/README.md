# 双Flash烧录次数校验（2026-10-29）

当前固件的次数同时保存到烧录器GD32内部Flash和外部SPI Flash。
每次烧录前，两份记录都必须通过HMAC-SHA256校验，记录内容必须完全一致，有限次数必须大于0；否则显示“次数记录异常”或“剩余次数不足”，禁止烧录。

## 升级

将本包 DAPlink.bin 用现有上位机/文件传输上传到设备 /update/DAPlink.bin，重新上电更新。DAPlink.hex 是从0x0800C000开始的应用镜像，不能当作含Bootloader的整片镜像。本次未向实物写入。
原有按固件设置次数的上位机可继续使用。“保存当前固件”或重新导入固件会设置当前文件的次数；其他正常账本中的固件次数保留。

## 保存和异常处理

- 正常烧录先同步预扣一次，失败时同步退回一次；目标烧录期间断电保留预扣的一次。只有双份写入、关闭并回读通过后才启动目标烧录。
- 双份写入之间掉电、外部镜像丢失/损坏/恢复旧备份，或内部记录与外部不一致时禁烧，不自动用其中一份修复另一份。通过上位机对当前固件重新保存次数可显式恢复；其他固件账本本身损坏时继续拒绝，避免丢弃/重置其他固件的次数。
- 未配置或缺少记录的固件默认零次，需要在上位机明确配置。已明确保存的“不限”仍支持，但同样要求双份校验通过。
- 升级保留能识别的旧BQT1/BQT2当前额度和旧账本内已记录的固件额度。旧版未记录的固件不会自动获得不限次数。升级中断也不会自动放行，可重新保存当前次数恢复。
- 当前外部镜像：0:/system/burnquota.chk；各固件历史额度账本：0:/system/burnquota.dat。当前记录包含固件完整文件名、次数、限制标志、序号及账本HMAC。固件身份沿用文件名，ASCII大小写不敏感。
- 内部次数区0x0801F800～0x0801FFFF；选择保存区0x0801F000～0x0801F7FF。新应用不覆盖这些页。保留原Bootloader和标准FLM工程。

## 校验范围与验证

使用HMAC-SHA256生成128位校验码，固件内密钥结合GD32唯一ID绑定设备。它认证次数数据，不加密目标固件，也不改变芯片读保护设置。仅恢复旧外部Flash会被识别；同时恢复两块Flash的同一套旧备份仍可匹配，这是本方案边界。原有上位机SET仍是管理员重设次数的入口。

verification保存当前构建、真实ARM Thumb代码模拟运行、篡改/回放、断电/写入错误、USB/上位机回归与独立审查记录。已完成本机验证；尚未做实物升级及断电试验。
历史账本暂未做压缩，每次烧录的校验时间随账本长度增长；日常空闲界面不会反复扫描。长期大量切换固件的性能仍需实物验证。
