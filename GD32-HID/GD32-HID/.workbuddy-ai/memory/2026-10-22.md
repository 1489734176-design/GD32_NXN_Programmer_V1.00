# 2026-10-22

## CDC_LED 飞线到 PA9

背景：PA8(USB_EN) 已验证通过，USB 正常。现在把 CDC_LED 从 PB5 飞线到 PA9 做验证。

### 改动（app: GD32-HID/GD32-HID，boot: Bootloader/Bootloader）
1. `DAPlink/inc/main.h`：`CDC_LED_Pin/Port` PB5/GPIOB → **PA9/GPIOA**（低电平点亮）。
   同时给 `TGT_TDI_Pin` 加注释：PA9 已被 LED 占用，TGT_TDI 实际不可用（原本也没人用）。
2. `USER/BSP/bsp_led.c`：`led_init()` 补 `rcu_periph_clock_enable(RCU_GPIOA)`
   （原来只开 GPIOB，LED 全在 PB5/6/7）。
3. `USER/DAPlink/DAP_config.h`：PA9 在 app 里原本是 **JTAG_TDI**，必须全部摘掉：
   - `PORT_JTAG_SETUP`：删掉 TDI 的 BOP 置高 + `gpio_init(OUT_PP)`
   - `PORT_SWD_SETUP`：删掉 TDI 的 `gpio_init(IN_FLOATING)`（否则每次 swd_init 都会把 LED 关掉）
   - `PORT_OFF`：删掉 TDI 的 `gpio_init(IN_FLOATING)`
   - `PIN_TDI_OUT`：改成空操作 `(void)bit;`（否则 JTAG/DAP_SWJ_Pins 会驱动 PA9，LED 乱闪）
   - `PIN_TDI_IN` 保留（只读，无害）
4. Bootloader 同步：`main.h` 的 CDC_LED 也改 PA9，`bsp_led.c` 补 RCU_GPIOA。
   Bootloader 没有 DAP_config.h，不用改别的。

### 加了上电自检
`bsp_led.h` 新增 `CDC_LED_SELFTEST`（默认 1），`run.c` 的 `led_task()` 开头
闪 3 下（120ms 亮/灭）。原因：**固件里根本没有 CDC 接口**，
`app_data.cdc_led_blink` 全文从没被置 1，CDC_LED 平时永远不会亮，
只有"长按中键关机 + 插充电"时三灯轮转（run.c:204）才会轮到它。
验证完把 `CDC_LED_SELFTEST` 改 0 即可。

### 编译/反汇编验证
- app：Code=53616 RO=6344 RW=840 ZI=19248，0 error 0 warning，`DAPlink.bin` 60332 字节
- boot：Code=27272 RO=5488 RW=436 ZI=16068，0 error 0 warning，`Bootloader.bin` 32964 字节
- `led_init`：`rcu_periph_clock_enable(0x603)` + `(0x602)`，第三个 `gpio_init` 的
  port=**0x40010800**(GPIOA)、pin=**0x200**(PA9) ✅
- `led_task`：`gpio_bit_reset(GPIOA,0x200)` → `vTaskDelay(0x78)` → `gpio_bit_set` → 循环 3 次 ✅
- `swd_init` 反汇编只剩 GPIOB(PB13/15/12) + GPIOA 的 **0x400**(PA10 nTRST)，**没有 0x200** ✅

### 硬件注意事项
- PA9 同时是 **TGT_TDI**（目标 JTAG 排针的 TDI 脚）。LED 挂上去后这根线会带 LED 电平，
  接目标时注意目标 TDI 的上/下拉不要和 LED 抢。JTAG 模式本来就废了（PA8=TDO），只用 SWD 无影响。
- USART2 用 PB10/PB11，USART0 未使用，MCO 未使能，PA9 无其它 AF 冲突。
- 如果 Bootloader 还没刷成新版（仍驱动 PB3），刷这个 app 仍然要短接 PB3↔PA8。

## SWDIO 从 PB15 换到 PB14

背景：板上 **PB14(pin27) 与 PB15(pin28) 短接在同一条 TGT_SWDIO 网络上**（原理图确认）。
用户要割 PB15 一侧（PB15 好割），把 PB15 释放出来，SWDIO 留在 PB14。

**关键事实：PB14 原本就是闲置的。** 固件里 SWDIO 的驱动和回读全走 PB15：
`DAP_config.h` 的 `JTAG_TMS_Pin` 同时被 `PIN_SWDIO_TMS_IN/SET/CLR`、`PIN_SWDIO_IN/OUT`、
`PIN_SWDIO_OUT_ENABLE/DISABLE`、`PORT_*` 共 13 处引用。
main.h 里的 `TGT_TMS_IN_Pin = PB14` 只是定义了，**全工程没有任何 .c 使用**。

### 改动
1. `USER/DAPlink/DAP_config.h:200`：`JTAG_TMS_Pin` **GPIO_PIN_15 → GPIO_PIN_14**（一行搞定，
   因为所有 SWDIO 操作都走这个宏）。
2. `DAPlink/inc/main.h`：`TGT_TMS_Pin` 也改 PB14，并加注释说明 PB14/PB15 原为短接、
   PB15 已割断可另作他用；`TGT_TMS_IN` 保留（同为 PB14，仍未使用）。

Bootloader 不用改（它没有 DAP_config.h，只有 PB3→PA8 的 USB_EN 相关改动；
其 main.h 里的 TGT_TMS/TGT_TMS_IN 也是死定义；`SWCLK_Pin` 是 PA14 不是 PB14）。

### 反汇编验证
`swd_init`：`MOV r5,#0x2000`(PB13 TCK) → `LSLS r3,r5,#1` = **0x4000(PB14)** 置高，
`gpio_init(GPIOB,OUT_PP,2M,0x4000)`。之前这里是 `LSLS #2` = 0x8000(PB15)。✅

编译：Code=53620 RO=6344 RW=840 ZI=19248，0 error 0 warning，`DAPlink.bin` 60336 字节。

### 待确认
- PB14/PB15 都是 FT（5V 容忍）脚，SWDIO 用它没问题。
- 割线后要量：PB14↔PB15 不通；PB14↔排针 TGT_SWDIO 仍 0Ω。
- 若 SWDIO 的外部上拉电阻挂在 PB15 那一侧，割断后会丢（固件读 SWDIO 用的是
  IN_FLOATING，靠目标板上拉，通常无影响）。
