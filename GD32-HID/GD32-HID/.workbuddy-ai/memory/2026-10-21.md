### 排障：飞线到 PA8 后进不了 Bootloader（结论：硬件接错，非代码问题）

用户回退到 0a21c76，反馈"长按 SW1 插 USB 进不了 Bootloader、检测不到内存卡"，
并说"蜂鸣档量 PA8 跟 R25 是通的"。

**关键事实（已核实）**：
1. **Bootloader 是独立工程** `D:/mym/NXN/6.Programmer/DAPlink/Bootloader`，
   占 0x08000000~0x0800BFFF；app 在 **0x0800C000**（map: LR_IROM1 Base 0x0800c000，
   Max 0x14000；`main.c:43 SCB->VTOR = FLASH_BASE|0xC000`）。

   **完全没被我改过** → 改 app 不可能影响 Bootloader 的 USB。
2. Bootloader `start_up()` 末尾 `if(read_key_left) update_flag = 2;` → 进 MSC（U 盘）模式，
   然后 `main()` 里 `usbd_init/usbd_connect`。所以"长按 SW1 插 USB"= 左键。
3. **原理图 USB_EN 电路**（SCH_P1_2026-10-20.pdf，MCU pin39=PB3=USB_EN）：
   `USB_EN --R26(1k)--> Q2(PNP) 基极`，`Q2 发射极 = 3.3V`，
   `Q2 集电极 --R6(1.5k)--> USB D+`，`R25(10k)` 是 **USB_EN → 3.3V 的上拉**。
   - USB_EN 低 → Q2 导通 → D+ 1.5k 上拉 → 枚举
   - USB_EN 高/悬空 → R25 把基极拉到 3.3V → Q2 截止 → **PC 完全看不到设备**

**病根推断**：R25 一端是 USB_EN、另一端是 **3.3V**。蜂鸣档量"PA8 跟 R25 通"
区分不了这两端——焊在哪端都会响。若焊在 3.3V 那端，USB_EN 被硬钉在 3.3V，
Q2 永远截止，**Bootloader 和 app 都枚举不了**，与现象完全吻合。

**决定性测量**（断电）：PA8 ↔ 3.3V 电阻
- ≈10kΩ → 焊对了（经 R25）
- ≈0Ω → 焊到 3.3V 端了，这就是病根
- ∞ → 线根本没通
补充判据：上电长按左键，若 OLED 有字（"APP UPDATE"/"BIN FAIL"/"FATFS FAIL"），
说明 Bootloader 在正常跑，只是 USB 死了 → 佐证 USB_EN 被拉死。

**风险**：若 PA8 被短到 3.3V，而 app 里 `usbd_dp_pullup(SET)` 把 PA8 拉低，
等于输出对 3.3V 硬短路，PA8 可能已损伤，需量 PA8↔GND / PA8↔3.3V 确认。

正确焊点：R25 **上端**（与 R26 相连、带 USB_EN 标签那端）或 R26 右端，绝不能用下端。

### 其它已排除项
- MCO 未被使能（只有 system_gd32f10x.c 里复位 CKOUT0SEL），PA8 不会被 AF 抢走。
- SPI Flash 用 PA4/PA5/PA6/PA7，与 PA8 不冲突。
- 两个工程的 `rcu_config()` 都有 `gpio_pin_remap_config(GPIO_SWJ_SWDPENABLE_REMAP,ENABLE)`
  → 关 JTAG 保 SWD，**自动释放 PB3/PB4/PA15**。所以 PB3 做 SPI1_SCK 是可行的。

### 待解决：Bootloader 怎么烧进去（鸡生蛋）
0x08000000 不能自己更新自己，app 也 SWD 不了自己。
- 方案A：第二个编程器（ST-Link/J-Link/另一块 DAPlink）SWD 烧 0x08000000 —— 最稳。
- 方案B：app 自举写 Bootloader 区。技术上可行：app 的 `main.c:43` 有
  `SCB->VTOR = FLASH_BASE | 0xC000`，擦 0x08000000 段时中断向量不受影响。
  但掉电中断有变砖风险（app 还在就能重试，理论上可恢复）。
