# Screen UI Implementation Plan

> **For agentic workers:** Use executing-plans inline. Track progress in .planning/2026-10-29-screen-ui.

**Goal:** Match the user's 16-pixel blue-label/yellow-value screen, inline chip model and two reserved firmware rows.

**Architecture:** Extend direct bitmap drawing with explicit RGB565 foreground, preserving monochrome APIs. Include color in field cache identity. Use paired fields and existing GBK-aware wrapping.

**Tech Stack:** GD32F103, ARMCC/Keil, C99, ST7789 RGB565, Python/Unicorn.

**Spec:** User request, reproduced in task_plan.md.

## Global Constraints
- Application text height 16 pixels; Chinese width 16, ASCII width 8.
- Labels LCD_BLUE (0x001F), values LCD_YELLOW (0xFFE0), background black.
- Chip label/value share a row. Firmware wraps below the value start, with an empty second row for fitting names.
- All colons use ASCII ':', matching Checksum. Four-character labels occupy 72 pixels; value x=80, width=232.
- Preserve encodings, SWD, quotas, persistence, USB and chip-name mapping. Keep bootloader compatible.

## Review Focus
- Exactly fitting firmware: second row empty.
- Mixed GBK/ASCII boundary: no split character or overlap.
- Long filename replaced by short/empty: no stale pixels.
- Identical refresh: no LCD writes; color-only change: repaint.
- Selected filename: black text on yellow, normal: yellow on black.
